# 含导航的语音智能体 — 设计方案

> 决策：C 档（自建 App）+ 开车语音交互场景
> 日期：2026-10-31

## 一、目标与非目标

**目标**
- 开车全程零屏幕交互，纯语音
- 一句话改目的地、问路况、问周边
- 记住用户偏好（不走高速、常去地点、常走时段）

**非目标**
- 不做地图渲染引擎（用高德导航 SDK）
- 不做辅助驾驶/车道级引导（那是车厂的活）
- 不做多平台，先 Android 手机支架场景

## 三、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 导航引擎 | 高德导航 SDK | 路网+实时路况+转向引导一体，无替代 |
| 备选 | 百度导航 SDK | 高德授权拿不到时退这个 |
| 定位 | 高德定位 SDK / FusedLocation | 与导航 SDK 同源更稳 |
| ASR | 系统 SpeechRecognizer 起步 → 讯飞/火山 | 先跑通再优化，别一上来上本地模型 |
| 唤醒 | M1 阶段用蓝牙耳机/方向盘按键触发 | 绕开 KWS 的功耗和误唤醒问题 |
| TTS | 系统 TTS 起步 → 讯飞/火山 | 导航播报质量要求高，后期换 |
| 大脑 | LLM API（自备 Key） | 意图解析 + 对话 |
| 回声消除 | 半双工（播报时暂停拾音） | 比 AEC 算法可靠 |
| 保活 | 前台服务 + `foregroundServiceType` | Android 14+ 必须声明 location/microphone |

## 四、模块划分

```
app
├── nav/          高德导航 SDK 封装（路线、导航状态、转向提示回调）
├── voice/
│   ├── asr       语音识别（可打断）
│   ├── tts       播报队列 + 优先级抢占
│   └── duck      播报时暂停拾音（半双工）
├── brain/        LLM 意图解析 → 结构化指令
│   ├── intent    改目的地 / 问路况 / 问周边 / 查时间
│   └── memory    偏好与历史（本地存储）
└── ui/           导航画面（全屏，开车时不承载交互）
```

**关键接口**：`brain` 只输出结构化指令，不直接操作 SDK。

```kotlin
sealed class Command {
    data class Reroute(val destination: String) : Command()
    data class AskTraffic(val segment: String?) : Command()
    data class AskNearby(val keyword: String, val radius: Int) : Command()
    data class QueryEta(val destination: String) : Command()
}
```

## 五、开车场景硬约束

1. **回声消除**：外放播报 + 麦克风同时工作是自激源头。半双工最稳，AEC 只作补充。
2. **优先级**：导航播报 > 用户对话回复。Agent 的 TTS 必须可被转向指令打断。
3. **零屏幕**：开车时屏幕只显示导航，所有 Agent 交互走语音。
4. **断网降级**：隧道/山区无网时，ASR 失败要明确提示，并保留按键触发路径。
5. **安全底线**：不做"帮你超速""抄近道"这类诱导；不接管油门刹车。

## 六、里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 | 环境 + Key + 官方 Demo | 能导航到指定地址 |
| M1 | 一句话改目的地 | 说"改去张掖西站"，3 秒内重算并继续导航 |
| M2 | 路况/周边问答 | "前面堵不堵"能答出具体路段和延误分钟数 |
| M3 | 记忆 + 主动提醒 | 记住"不走高速"，下次规划自动避开 |

**M1 是价值核心**：做完这一条，体验就超过高德自带智能体。

## 七、风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 高德导航 SDK 授权拿不到 | 方案归零 | M0 先验，拿不到退 A 档 |
| 回声消除做不好 | 语音完全不可用 | 半双工兜底 |
| 厂商 ROM 杀后台 | 导航中断 | 前台服务 + 白名单引导 |
| 断网 ASR 失效 | 关键场景聋 | 本地 ASR 或按键兜底 |
| 开车分心责任 | 安全与合规 | 全程语音、不做复杂交互 |
